# 拾语 · 个人会话档案馆

把设备里的个人会话整理到自己的 NAS 或家庭服务器，按账号、联系人和时间翻阅旧对话，找回文件，也回顾一段时间的交流。

这是供个人和朋友使用的工具，采用闭源二进制分发。公开仓库提供说明、部署文件、可选组件和客户端，不包含项目源码或使用者的数据。

## 部署

基础服务只运行一个容器，内含网页、Rust 服务和 PostgreSQL，使用一个网页端口、一个持久化目录。当前提供 Linux x86_64 镜像：[`xuelingyun/shiyu:dev`](https://hub.docker.com/r/xuelingyun/shiyu)。`dev` 是滚动预览频道，具体构建号在网页“设置”中查看；更新由使用者手动执行，不随页面访问自动升级。

在 NAS 的数据盘上准备一个独立目录，放入本仓库的 `compose.yaml` 和 `.env.example`。下面的 `/srv/shiyu` 是通用 Linux 示例；NAS 应使用其文件管理器中可见的应用数据目录，极空间需使用已挂载的用户数据盘路径，不能照抄到系统盘。

```sh
mkdir -p /srv/shiyu/data
cd /srv/shiyu
cp .env.example .env
```

编辑 `.env`，把 `SHIYU_BIND_IP` 改成 **这台 NAS 自己的局域网 IP**，例如 `192.168.1.20`。保留默认 `127.0.0.1` 时，只能在 NAS 本机访问。其他参数通常可保持默认：

```dotenv
SHIYU_IMAGE=xuelingyun/shiyu:dev
SHIYU_BIND_IP=192.168.1.20
SHIYU_HTTP_PORT=18930
SHIYU_DATA_DIR=./data
SHIYU_MEMORY_MB=768
SHIYU_CPUS=2.0
```

然后执行：

```sh
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps
```

打开 `http://你的NAS局域网IP:18930/`。首次启动需要初始化数据库，比之后启动稍久。以容器健康状态和页面实际打开为准。模板使用 host 网络，不需要另加 `ports`、特权模式或 Docker socket，也不对外开放数据库端口。768 MiB 是内存上限；系统和其他应用仍需要留有余量。

不使用 Compose 时，可以在部署目录运行随附的 CLI 脚本，两种方式二选一：

```sh
export SHIYU_BIND_IP=192.168.1.20
sh ./docker-run.sh
docker logs --tail 100 shiyu-core
docker exec shiyu-core /usr/local/bin/shiyu-core healthcheck
```

### 极空间及虚拟共享目录

如果 NAS 的共享目录通过虚拟文件系统提供，请使用 Docker 本地数据卷版 [compose.volume.yaml](compose.volume.yaml)。极空间实测：虚拟共享目录直接绑定时，数据库初始化失败；改用现有 Docker 数据盘上的本地卷后正常启动。Docker 的数据盘应有足够容量。

数据卷版与上面的目录绑定版二选一。准备同一份 .env 后使用：

```sh
docker compose -f compose.volume.yaml config --quiet
docker compose -f compose.volume.yaml pull
docker compose -f compose.volume.yaml up -d
```

没有 Compose 命令时，用 SHIYU_STORAGE=volume sh ./docker-run.sh；可通过 SHIYU_VOLUME_NAME 指定卷名。若已在 Docker 中载入同一镜像，CLI 可加 SHIYU_PULL_POLICY=never。Docker Hub 无法直连时，需要设备本身已有的出站网络路径，普通用户无需为了应用修改 Docker 全局配置。

数据卷由 Docker 管理。不要使用 down -v 清理服务；迁移前按文档导出档案，或在停止实例后按 Docker 的卷迁移方式搬运完整数据。

## 开始使用

采集端：[Windows x64 开发版（便携包）](https://github.com/dinaaihzx123/shiyu-components/releases/tag/desktop-dev)。解压整个包后打开 `Shiyu.exe`。升级请沿用原配置和队列目录，避免重新建立同步进度。部分图片转换和视频缩略图所需的媒体支持，可在采集端设置中按需下载。

1. 首次向导中选择单用户或多用户模式，创建管理员账号和密码；这两步必须完成。
2. 选择媒体保存类型和回收站期限，后续还可调整。额外媒体默认不保存，回收站默认30天，可选1–365天。
3. 可选功能可以跳过。进入后，在正常登录会话软件的电脑上打开兼容的采集端，自动查找目录、发现或填写服务地址，完成首次配对。
4. 先选择少量会话验证，再按需要同步更多内容。窗口缩到通知区后可继续同步；完全退出会停止采集。

在“聊天档案”切换账号和个人／群聊／功能分组，按名称、时间、消息量或置顶状态排序。图片、视频、表情、语音、文件、个人头像、群成员头像和群图标均由使用者选择保存；头像变化后更新为新图。原图／原视频还需要开启对应媒体保存，源端没有的文件会明确显示暂缺。

断点与已确认回执用于继续同步；快速校验检查索引、文件存在和大小，**不等同于逐文件完整内容校验**。暂缺原件与已保存缩略图分别管理，已确认内容不应被计作本次新增。

单用户模式可管理自己的多个来源账号。多用户模式中，每个用户管理自己的档案，管理员负责系统和用户管理，默认不能阅读他人的会话。

## 可选组件

在“设置 → 可选组件”选择功能，服务自动下载、校验签名并安装到持久化目录，启用成功才显示对应设置。重建容器后保留已安装组件，所有组件共用一个容器。下载设置可填写代理；代理只影响组件下载，不修改 NAS 或 Docker 的代理。

当前可用的是 AI 报告组件；安装后自行配置兼容的模型服务。不开启时只用本地统计回顾，AI 输入区域隐藏。向量索引、NAS 常驻来源和额外媒体工具运行组件尚未发布，不作为可用功能。基础媒体浏览无需额外安装媒体工具。

离线设备可上传发行者提供的 `.sycomp` 签名包。不要导入来源不明的组件；发行包必须与系统和 CPU 架构兼容。

## 保存、恢复与迁移

数据库状态、各账号占用、内存查询缓存、归档导入／导出、自动备份和维护操作在设置中管理。内容先进入回收站，可恢复所选记录或清空；这些操作不改动来源设备里的原记录，独立导出和备份也需分别管理。

官方手机备份原包的冗余保存处于测试阶段，不解密其中正文。原包回传流程尚未完成官方客户端与手机的恢复验收，不能据此保证能够恢复；拾语档案也不能直接反向写入官方聊天数据库。macOS 采集适配和恢复到官方客户端的能力，只有在明确验收的版本中才作为已支持功能。

迁移拾语时须正常停止实例，搬移完整持久化目录与对应镜像，保留数据库、媒体、组件、设置及密钥，尤其不能遗漏 `app/master.key` 和 `system`。同一目录不能被两个实例同时写入。跨 CPU 架构或数据库大版本的迁移需要另行验证。

当前聊天正文尚未实现整库静态加密。账号隔离、配置密钥封装、加密归档备份不能代替磁盘加密；数据目录应保持合适的系统权限，默认按局域网部署。
