# 拾语 · 个人会话档案馆

拾语用来把设备中的个人会话整理到自己的 NAS 或家庭服务器。需要翻看一段旧对话、寻找一份文件，或回顾一段时间的交流时，打开浏览器即可查看。

这是供个人和朋友使用的小工具，采用闭源二进制分发。公开仓库只提供使用说明、部署文件、组件和客户端发行包，数据由使用者保存在自己的设备上。

## 可以做什么

- 按账号、会话和时间浏览档案，支持搜索与分组排序。
- 按需保存图片、视频、语音、表情、附件及头像，媒体默认不缓存。
- 将单条内容或整个会话移入回收站，在设定期限内恢复。
- 查看同步进度、数据库状态及存储占用，管理导入、导出与归档备份。
- 选择单用户或多用户模式。多用户之间隔离，管理员默认也不能查看他人的会话。
- 使用本地统计回顾；有需要时安装 AI 报告组件，再自行配置模型。

当前发行说明对应 Linux x86_64 服务端。其他架构须使用明确提供并验收过的对应镜像。NAS 常驻来源和向量索引运行组件尚未发布，对应设置保持隐藏。客户端需使用与服务端兼容的版本；macOS 真实数据读取仍在适配，不作为已完成的采集能力。

## 部署前准备

适用于支持 Docker Engine 与 Docker Compose v2 的 Linux NAS。基础版运行一个容器，内含服务、网页和 PostgreSQL；只需一个网页端口和一个持久化目录。默认内存上限 768 MiB、CPU 上限 2 核，上限不是常驻占用，设备还需要为系统及其他应用保留余量。

请为新实例使用独立目录，例如 `/srv/shiyu`。已有实例保留其原配置与完整数据目录，不要用新安装的空目录覆盖。

当前尚未发布 Docker Hub 正式镜像。先取得本次发行提供的离线镜像文件，核对发行说明中的 SHA256 后导入：

```sh
docker load --input shiyu-core-linux-amd64.tar
docker image ls shiyu-core
```

镜像文件名及标签以实际 Release 附件为准；没有提供的包不视为已发布。本页不要求自行编译源码。以后若提供镜像仓库，只需把 `SHIYU_IMAGE` 换成发行说明中的固定标签或摘要。

## 使用 Docker Compose

把随附的 `compose.yaml`、`.env.example` 放入部署目录，将 `.env.example` 复制为 `.env`：

```sh
mkdir -p /srv/shiyu/data
cd /srv/shiyu
cp .env.example .env
```

按本机情况编辑 `.env`。例如镜像已导入、NAS 局域网地址为 `192.168.1.20`：

```dotenv
SHIYU_IMAGE=shiyu-core:rust-20261106-rc12
SHIYU_DATA_DIR=./data
SHIYU_BIND_IP=192.168.1.20
SHIYU_HTTP_PORT=18930
SHIYU_MEMORY_MB=768
SHIYU_CPUS=2.0
TZ=Asia/Shanghai
```

`192.168.1.20` 是示例，换成自己 NAS 的真实 LAN IP。模板默认 `127.0.0.1`，只允许 NAS 本机访问。模板使用 host 网络，不再添加 `ports`。配置与资源参数按 [Docker Compose 官方文档](https://docs.docker.com/reference/compose-file/services/) 设置。

```sh
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail 100 shiyu
```

随后打开 `http://你的NAS局域网IP:18930/`。首次初始化会创建数据库和内部凭据，通常比后续启动稍久；以容器健康检查和页面实际可访问为准。

## 使用 Docker CLI

不使用 Compose 时，可在部署目录运行随附的 `docker-run.sh`。它与 Compose 使用相同的权限、持久化目录、内存限制、日志轮转和正常退出等待时间：

```sh
cd /srv/shiyu
export SHIYU_IMAGE=shiyu-core:rust-20261106-rc12
export SHIYU_BIND_IP=192.168.1.20
sh ./docker-run.sh
docker ps --filter name=shiyu-core
docker logs --tail 100 shiyu-core
docker exec shiyu-core /usr/local/bin/shiyu-core healthcheck
```

Compose 与 CLI 二选一，不要用同一名称重复创建。无需特权模式、Docker socket 或另开数据库端口；管理进程在容器内将数据库和应用分别降权运行。

## 第一次使用

1. 选择单用户或多用户模式。个人使用通常选单用户，可管理自己的多个来源账号。
2. 创建管理员账号和访问密码；这两步必须完成。
3. 选择媒体保存类型、原图／原视频策略及回收站保留天数。可跳过，媒体默认关闭，回收站默认 30 天，范围 1–365 天。
4. 选择是否安装可选功能。可跳过，之后在设置中调整。

进入档案馆后，在正常登录聊天客户端的电脑上启动兼容的桌面采集端。自动查找来源目录，找不到时再手动选择；发现服务端或填写档案馆地址，完成首次配对，确认来源账号后开始同步。每个来源账号保存在独立空间，不混合显示。

首次同步可能较久；之后按同步计划增量处理。进度以客户端和服务端的实际状态为准，单纯“连接成功”不代表已同步完成。同步过程中保留桌面采集端运行；首次只选择少量会话和必要媒体，更方便确认配置是否符合自己的需要。

## 日常使用

在「聊天档案」中切换账号、个人／群聊／功能分组，按需要搜索、排序和浏览。缓存开关在「设置 → 缓存与存储」中调整；启用原图或原视频还需要开启对应图片或视频保存。头像变化后，以新图片更新显示。

删除内容会先进入回收站，可恢复所选记录；永久删除和清空会移除档案中的对应内容，不影响来源客户端本身。已有导出文件和独立备份仍须分别管理。

在「设置 → 可选组件」安装需要的功能，镜像内置发行源。可以配置仅用于组件下载的代理；离线设备可上传 `.sycomp` 签名包。未安装或未启用的组件不显示对应配置。当前可用的是 AI 报告组件，安装后再填写模型地址、名称和密钥；不配置模型也能使用本地统计回顾。下载组件本身不会向模型发送会话内容。

数据库状态、存储用量、归档导入与导出、备份和回收站策略均在设置中管理。官方备份原文件只作为原样冗余保存，不解密其中正文；不承诺把档案导出反向写回来源软件。

## 数据与迁移

持久化目录应完整保留，包含数据库、账号、媒体、组件、设置以及密钥。不要只移动其中的数据库目录，也不要遗漏 `app/master.key` 或 `system`。

同架构、同数据库大版本的迁移，需要先正常停止实例，再搬移完整持久化目录及对应固定镜像，确保目标机器没有同时写同一目录。跨 CPU 架构、数据库大版本或恢复到来源软件，需要独立验证，不能直接套用文件复制流程。

当前会话正文尚未做整库静态加密。网页登录、用户隔离、敏感配置加密和加密归档备份各有作用，不能替代磁盘层加密。建议数据目录只授权给需要的系统账号，服务按局域网部署。
